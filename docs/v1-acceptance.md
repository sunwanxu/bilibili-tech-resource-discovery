# v1 验收标准

v1 只有同时通过离线、低频真实数据和首次用户流程三类测试，才能替换 v0.8。

## 1. 首次使用

- 全新 Windows 用户可以双击安装，或把 GitHub 地址发给支持 Skill 的 AI 完成同一安装流程。
- 不要求预装 Python、Firefox、Cookie 导出插件，也不要求手工编辑环境变量。
- 未配置任何 API key 时，公开模式和 B 站页面搜索仍可运行。
- 用户同意登录后，只打开项目专属的可见 B 站窗口；不读取日常 Edge Cookie 数据库。
- 安装、登录、搜索失败都有非技术化恢复提示和稳定机器错误码。

## 2. 自然语言交互

- 初学者只说“我想学画 STM32 PCB”也能进入正确流程。
- 问题按目标、水平、范围逐步出现，最多三个核心问题；用户要求直接搜索时不继续盘问。
- 混合学习/资源需求会先确认主模式。
- 登录、全量验证、外部付费/密钥和原文保留都必须先说明利弊再获得同意。

## 3. 搜索质量

- 标准模式目标为 15–30 个去重候选，精选 5–10 个；深度模式允许更多，但受请求预算约束。
- 候选数量不依赖连续发送大量关键词；一页、缓存、UP/合集/相关视频共同扩展覆盖。
- 型号、年份、A–Z 题号、缩写、引号短语和用户核心主题不会被查询规划丢弃。
- 过滤器不能出现“全部拒绝后全部恢复”；每个保留或排除项都有机器可读原因。
- 学习模式和资源模式在同一组候选上会产生不同且可解释的排序。

## 4. B 站请求与失败恢复

- 每次运行记录计划请求、实际请求、缓存命中、跳过和预算余额。
- 触发 HTTP 412 后，搜索、预览、字幕和评论等所有新 B 站请求均为 0。
- 412 前取得的候选和已完成深读必须保留，并生成 `partial_success` 报告。
- 不自动重试 412；客户端建议等待与服务端实际状态分开表达。
- 单个坏 URL、超时或解析错误只影响该候选，不会导致整轮无报告。

## 5. 视频和资源证据

- discover 输出的纯 AV 数字、`av...`、BV 和完整 URL 都能直接交给 analyze。
- 显式候选 URL 配合深读时一定进入视频详情、简介、字幕和可选评论流程。
- 每条外链保留发现位置：简介、字幕、评论、UP 页面、相关文章或用户输入。
- 资源验证区分存在性、访问状态、文件完整性、可用性和许可证作用域。
- 登录/网盘/群聊等无法自动读取但可能有价值的链接仍会列出并标记人工步骤。

## 6. 数据与输出

- CLI 始终输出 UTF-8 机器摘要和固定 `latest.json` 路径，不依赖 PowerShell 渲染 Markdown。
- 报告写入使用 checkpoint 和原子替换；失败运行不覆盖最近一次成功报告。
- 默认数据中没有 Cookie、API key、媒体签名直链、评论作者身份或无关 raw extractor 字段。
- JSON schema 有版本号，错误有稳定 `code/category/phase/recoverable` 字段。

## 7. 发布门槛

- 所有单元和契约测试离线运行，不访问 B 站。
- Windows 全新工作区连续安装、升级、回滚各三次，无 editable `.pth` 或路径漂移。
- 至少用学习、PCB、嵌入式代码、AI 工具和竞赛方案五类真实需求做低频验收。
- 与 v0.8 对照时，候选覆盖、有效外链数、失败后可恢复性和用户操作数至少三项明确改善，且没有
  新的 P0 回归。
